⏺ Reply:
  Here's what I found and what I'd do.
  
  **What's there.** `code/placements.R` scrapes the Dyson placements table and writes `data/placements.csv` (109 rows; columns `year, name, position, organization, postdoc`). The `organization` column has ~105 distinct free-text strings — mixed granularity (`"Brown"`, `"NUS"`, `"DTUM"`, `"Stout"`), embedded departments (`"Purdue University, Department of Agricultural Economics"`), occasional location hints (`"Peking University (Beijing)"`, `"KDI School … (Korea)"`, `"University of Alberta, Canada"`), and a few two-organization entries (`"National Bureau of Economic Research, Claremont McKenna College"`).
  
  **Approach: a hand-curated lookup table, joined in the script.**
  
  1. **New file `data/org_country.csv`** with two columns, `organization, country`, one row per distinct organization string exactly as it appears in the scraped data (after `trimws`). I'd populate it myself from knowledge of the institutions, and mark the handful I'm unsure about in my reply so you can check them.
  2. **Edit `code/placements.R`**: after the `postdoc` flag and before `write.csv`, read the lookup, `match()` on the exact organization string, and add `placements$country`. If any organization isn't in the table, print the unmapped names and leave `country = NA` (warn rather than stop, so a re-scrape never fails when a new graduate appears — you just extend the table). Column order: `year, name, position, organization, country, postdoc`.
  
  **Why a lookup table rather than the alternatives.**
  - Regex heuristics ("University of X" → US) break immediately on `University of Sydney`, `University of Bern`, `University of Calgary`.
  - Geocoding / ROR / web APIs add a network dependency and choke on abbreviations like `NUS`, `IIMA`, `DTUM`, `Brown`.
  - The dataset is ~100 rows; a table is trivial to maintain, fully reproducible, and the script rewrites `placements.csv` on every run, so the mapping has to live outside that file anyway.
  
  **Judgment calls I'd make unless you say otherwise.**
  - **Country labels:** plain English short names (`United States`, `United Kingdom`, `South Korea`, `Hong Kong`, …). I can add an ISO3 code column too if you want it for later joins.
  - **International organizations** (World Bank, IMF, Inter-American Development Bank, USAID): `United States` — headquarters location. Alternative is a separate "International" label; say which you prefer.
  - **Hong Kong**: `Hong Kong`, not `China`.
  - **Multinationals** (Uber, Citibank, Morgan Stanley, Capital One, StoneX, Acadian): country of headquarters (US), since the `position` text doesn't give an office location.
  - **Two-org entries**: country of the first-listed organization (both examples are US anyway).
  - **Uncertain ones I'd flag:** `DTUM` (likely DTU Management, Denmark), `Stout` (US consulting firm), `Cooper/Smith` (US), `Econic Partners LLC` (US), `Center for Governmental Research` (US, Rochester NY).
  
  If that all sounds right — or you want ISO codes / a different rule for international orgs — tell me and I'll write it.
