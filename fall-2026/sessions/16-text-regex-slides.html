From text to variables

The Federal Open Market Committee decided today to establish a target range for the federal funds rate of 0 to 1/4 percent.

Since the Committee’s last meeting, labor market conditions have deteriorated, and the available data indicate that consumer spending, business investment, and industrial production have declined. Financial markets remain quite strained and credit conditions tight. Overall, the outlook for economic activity has weakened further.

  • A pattern finds 0 to 1/4 percent → lower = 0 and upper = 0.25 (percent).
  • A count of words on a finance word list: the statement has 403 words. 8 are negative (the 4 in red are in these two paragraphs) and 2 are positive.
  • Net tone = 100 × (positive − negative) / words = 100 × (2 − 8) / 403 = −1.49.
  • Run on all 171 statements from 2006 to 2026, each method gives a column you can plot and compare with other data.

What a regular expression is

  • A regular expression (regex) is a pattern, written as a string, that describes a set of texts. A function reads the pattern and finds the stretches of text that fit it, called matches.
  • Most characters match themselves: the pattern "rate" finds the letters r, a, t, e in that order. These are literals.
  • A few characters have a special meaning, such as ?, which makes the piece before it optional. These are metacharacters.
  • The same syntax works in most programming languages and text editors.
R Console; needs stringr
# install.packages(c("stringr", "stopwords"))   # once
library(stringr)               # text functions; every name starts with str_
words <- c("color", "colour", "colr", "Colour")
str_detect(words, "colou?r")   # TRUE if the string contains a match; ? makes the u optional
#> [1]  TRUE  TRUE FALSE FALSE
str_view(words, "colou?r")     # the strings that match, each match in < >
#> [1] │ <color>
#> [2] │ <colour>
str_detect(words, regex("colou?r", ignore_case = TRUE))   # upper and lower case match alike
#> [1]  TRUE  TRUE FALSE  TRUE

Matching is case-sensitive, so “Colour” does not match until ignore_case = TRUE inside regex() turns that off.

Metacharacters

Symbol Means Pattern Example match
. any one character r.te rate, rite
[ ] one character from the set [0-9] 4
[^ ] one character not in the set [^0-9] the - and / in 4-3/4
? the piece before, zero or one time rates? rate, rates
* the piece before, zero or more times 10* 1, 10, 100
+ the piece before, one or more times [0-9]+ 2026
{n} the piece before, exactly n times [0-9]{4} 2026
^ $ the start, the end of the text ^The “The” at the start
| the piece on either side raise|lower raise, lower
( ) a group, whose match R can return alone ([0-9]+)% 4% (group: 4)
\\ the next character is plain (in R, typed twice) \\. a period

Shortcuts: \\d a digit, \\s a space or line break, \\w a letter, digit or underscore, \\b the edge of a word. In R each backslash is written twice: you type "\\d" and the pattern receives \d. A piece is one character, a class in brackets, or a group.

Character classes [ ] and \\d

R Console; needs stringr
# a sentence from the Fed's policy statement of 22 March 2023
x <- "the Committee decided to raise the target range for the federal funds rate to 4-3/4 to 5 percent."
str_view(x, "\\d")
#> [1] │ the Committee decided to raise the target range for the federal funds rate to <4>-<3>/<4> to <5> percent.
str_view(x, "[0-9/-]")
#> [1] │ the Committee decided to raise the target range for the federal funds rate to <4><-><3></><4> to <5> percent.
str_view(x, "[^a-z ]")      # ^ inside brackets: any character NOT in the set
#> [1] │ the <C>ommittee decided to raise the target range for the federal funds rate to <4><-><3></><4> to <5> percent<.>
  • Character class: characters in brackets. It matches any one of them.
  • Inside brackets, 0-9 means any digit and a-z any lowercase letter. A hyphen placed last, as in [0-9/-], is a plain hyphen.
  • [^ ] matches any one character NOT in the set. The set in [^a-z ] is the lowercase letters and the space, so it catches the capital C, the digits, the - and the /, and the final period.
  • \\d: one digit, the same as [0-9].
  • The Fed writes rates as a whole number and a fraction: “4-3/4 percent” is 4.75 percent.

The dot and the escape

R Console; needs stringr and x
str_view(c("rate", "rite", "r8te", "rte"), "r.te")   # . : any one character
#> [1] │ <rate>
#> [2] │ <rite>
#> [3] │ <r8te>
str_view(x, "\\.")           # \\. : a period
#> [1] │ the Committee decided to raise the target range for the federal funds rate to 4-3/4 to 5 percent<.>
c(str_count(x, "."), str_count(x, "\\."))
#> [1] 97  1
  • The dot .: any one character.
  • The dot needs exactly one character, so “rte” does not match. str_count() counts the matches in each string.
  • Escape: a backslash that turns a metacharacter back into a plain character: \\. a period, \\$ a dollar sign, \\? a question mark, \\( a parenthesis.
  • x has 97 characters. "." matches each of them, and "\\." only the period.

Quantifiers

R Console; needs x
str_extract_all(x, "[0-9/-]+")            # + : one or more of the piece before
#> [[1]]
#> [1] "4-3/4" "5"
str_extract(x, "\\d+-\\d+/\\d+")           # a whole number, a hyphen, a fraction
#> [1] "4-3/4"
str_detect(c("1/4 percentage point", "1/2 percentage points"), "percentage points?")
#> [1] TRUE TRUE
str_extract(c("year 2026", "26"), "\\d{4}")   # {4} : exactly four digits
#> [1] "2026" NA
  • Quantifier: a mark after a piece (one character, a class in brackets, or a group) saying how many times it may repeat: + one or more, * zero or more, ? zero or one, {4} exactly four.
  • str_extract() returns the first match in each string, or NA. str_extract_all() returns every match, as a list with one element per string (the [[1]]).

Anchors and word boundaries

R Console; needs stringr
s <- c("rate", "the rate rose", "moderate", "rates")
str_detect(s, "rate")             # the literal also matches inside other words
#> [1] TRUE TRUE TRUE TRUE
str_detect(s, "\\brate\\b")       # \\b : the edge of a word
#> [1]  TRUE  TRUE FALSE FALSE
str_detect(s, "^rate$")           # ^ : start of the text; $ : end of the text
#> [1]  TRUE FALSE FALSE FALSE
  • Anchor: ^ pins the pattern to the start of the text and $ to the end. With both, the whole string must match. Inside brackets, ^ means NOT.
  • Word boundary \\b: the edge between a letter, digit or underscore and anything else: a space, a punctuation mark, or the start or end of the text.
  • False positive: text the pattern catches but should skip, such as “moderate” when you want the word “rate”. False negative: text it misses but should catch, such as “rates” under \\brate\\b.

Capture groups ( )

R Console; needs stringr
rates <- c("4-3/4", "1-1/2", "5")             # rates as the Fed writes them
m <- str_match(rates, "(\\d+)-(\\d+)/(\\d+)")  # whole number, numerator, denominator
m
#>      [,1]    [,2] [,3] [,4]
#> [1,] "4-3/4" "4"  "3"  "4" 
#> [2,] "1-1/2" "1"  "1"  "2" 
#> [3,] NA      NA   NA   NA
as.numeric(m[, 2]) + as.numeric(m[, 3]) / as.numeric(m[, 4])   # 4 + 3/4 = 4.75
#> [1] 4.75 1.50   NA
  • Capture group: a part of the pattern inside ( ). str_match() returns the whole match in column 1, then one column per group, in the order the groups open.
  • The groups split “4-3/4” into 4, 3 and 4, so the last line can compute 4 + 3/4 = 4.75.
  • “5” has no fraction, so the pattern finds no match and the whole row is NA.

Alternatives |

R Console; needs stringr
# phrases from the Fed statements of 8 Aug 2006, 22 Mar 2023 and 16 Dec 2008
phrases <- c("keep its target for the federal funds rate at 5-1/4 percent",
             "raise the target range for the federal funds rate to 4-3/4 to 5 percent",
             "establish a target range for the federal funds rate of 0 to 1/4 percent")
str_match(phrases, "(?:at|to|of) ([0-9/-]+) percent")
#>      [,1]               [,2]   
#> [1,] "at 5-1/4 percent" "5-1/4"
#> [2,] "to 5 percent"     "5"    
#> [3,] "to 1/4 percent"   "1/4"
  • at|to|of matches at, to or of. (?: ) groups the three words without adding a column, so the number lands in column 2.
  • Rows 2 and 3 return only the upper end of the range:
    • The pattern needs a space and “percent” right after the number.
    • After “to 4-3/4” comes “to 5”, so the search moves on and matches “to 5 percent”.
    • Getting both ends takes a second number group.

The functions for each task

Task and result stringr base R
find, validate
TRUE or FALSE		 str_detect(x, p) grepl(p, x)
count
a number per string		 str_count(x, p) lengths(regmatches(x, gregexpr(p, x)))
extract
first match, or NA		 str_extract(x, p) regmatches(x, regexpr(p, x))
groups
match, then groups		 str_match(x, p) regmatches(x, regexec(p, x))
extract all
a list of matches		 str_extract_all(x, p) regmatches(x, gregexpr(p, x))
replace
the new strings		 str_replace_all(x, p, r) gsub(p, r, x)

Result: what the stringr function returns. x is the text, p the pattern and r the replacement. Base R puts the pattern first, and its extract functions drop strings with no match. Chatbots write either style.

Validating a format

R Console; needs stringr
fips <- c("06037", "6037", "36109", "3610A", " 36109")   # US county codes
str_detect(fips, "^\\d{5}$")         # exactly five digits, nothing before or after
#> [1]  TRUE FALSE  TRUE FALSE FALSE
str_detect(fips, "\\d{5}")           # without the anchors, " 36109" passes
#> [1]  TRUE FALSE  TRUE FALSE  TRUE
fips[!str_detect(fips, "^\\d{5}$")]  # the values that fail
#> [1] "6037"   "3610A"  " 36109"
dates <- c("2026-10-22", "10/22/2026", "2026-1-5")
str_detect(dates, "^\\d{4}-\\d{2}-\\d{2}$")   # year-month-day, two digits each
#> [1]  TRUE FALSE FALSE
  • Validation: checking that every value has the format it should, before you merge or analyze the data.
  • A FIPS code is the US government’s five-digit code for each US county: two digits for the state, three for the county. Read as a number, “06037” (Los Angeles County, California) becomes 6037, and a merge on it fails.

Extracting numbers

R Console; needs stringr
prices <- c("$1,250", "price: $99.99", "free", "$52,000")
str_extract(prices, "[0-9,.]+")             # digits, commas and periods
#> [1] "1,250"  "99.99"  NA       "52,000"
ages <- c("<1", "1-5", "5-10", "15+")        # age groups in a mortality table
str_match(ages, "(\\d+)(?:-(\\d+))?")         # group 1: the first number; group 2: the second
#>      [,1]   [,2] [,3]
#> [1,] "1"    "1"  NA  
#> [2,] "1-5"  "1"  "5" 
#> [3,] "5-10" "5"  "10"
#> [4,] "15"   "15" NA
  • Extraction: keeping only the part of each string that matches.
  • str_extract() returns the match as text.
  • str_match() returns one column per group, so “5-10” splits into “5” and “10”. (?:-(\\d+))? makes the hyphen and the second number optional together; when they are missing, group 2 is NA.
  • The pattern returns 1 for “<1” and 15 for “15+”. You code by hand that “<1” starts at 0 and that “15+” has no upper end.

Replacing and cleaning text

R Console; needs prices
amount <- str_extract(prices, "[0-9,.]+")       # "free" has no digits, so NA
as.numeric(str_replace_all(amount, ",", ""))    # drop the commas, then convert
#> [1]  1250.00    99.99       NA 52000.00
str_squish("  Federal   Reserve \n Board ")     # \n: a line break; result: one space between words
#> [1] "Federal Reserve Board"
# month/day/year becomes year-month-day
str_replace(c("10/22/2026", "01/05/2026"), "(\\d{2})/(\\d{2})/(\\d{4})", "\\3-\\1-\\2")
#> [1] "2026-10-22" "2026-01-05"
  • Replacement: rewriting what the pattern matches. str_replace() changes the first match, str_replace_all() every match.
  • Backreference: \\1, \\2 and \\3 in the replacement stand for what groups 1, 2 and 3 matched. The US writes dates month/day/year (10/22/2026), so the replacement puts the year first: 2026-10-22.
  • as.numeric("1,250") gives NA, which is why the commas go first.

Testing a pattern

R Console; needs stringr
should_match <- c("the federal funds rate", "longer-term interest rates")
should_skip  <- c("at a moderate pace", "to generate sustained improvement")
str_detect(should_match, "\\brate\\b")
#> [1]  TRUE FALSE
str_detect(should_skip, "\\brate\\b")
#> [1] FALSE FALSE
str_detect(should_match, "\\brates?\\b")      # ? makes the "s" optional
#> [1] TRUE TRUE
str_detect(should_skip, "\\brates?\\b")
#> [1] FALSE FALSE
str_detect(should_skip, "rate")               # without \\b, "moderate" and "generate" match
#> [1] TRUE TRUE
  • Test a pattern on strings with a known answer first. Goal here: the word “rate” or “rates”, and not “moderate” or “generate”.
  • Should-match and should-skip tests: short vectors of real strings the pattern must catch and must leave alone, rerun after every change.
  • \\brate\\b misses “rates” (false negative); "rate" catches both skip strings (false positives); \\brates?\\b passes both.
  • Copy test strings from the documents. When the corpus shows a case the pattern gets wrong, add that string to one of the two vectors.

# 3. Replacement: drop the commas with str_replace_all(), then as.numeric().
# 4. Read the result next to income. Which answers give NA or a wrong number?

R Console; needs stringr
income <- c("$52,000", "48500", "Income: $61,250.00", "N/A", "about 40k",
            "$1,000,000")
ok_pat <- "^\\$?[0-9,]+(\\.\\d{2})?$"
str_detect(income, ok_pat)
#> [1]  TRUE  TRUE FALSE FALSE FALSE  TRUE

#> [1]   52000   48500   61250      NA      40 1000000

Three answers pass: “$52,000”, “48500” and “$1,000,000”. “about 40k” becomes 40, a thousand times too small, with no warning. It fails step 1, which is how you find it.

Uses only the functions of this part. The $ needs an escape because, on its own, $ is the end anchor. Without ^ and $, “Income: $61,250.00” passes step 1. “N/A” gives NA in step 2, which is the right answer for a missing value.

The Fed’s policy statements

  • The Federal Reserve (“the Fed”) is the US central bank.
  • Its Federal Open Market Committee (FOMC) sets the policy interest rate. It meets eight times a year and publishes a statement after each meeting. A few statements follow unscheduled meetings.
  • The federal funds rate is the rate banks charge each other for overnight loans. The Fed steers it.
  • The target range is the band the FOMC announces for that rate. “4-3/4 to 5 percent” means 4.75 to 5. Before 16 December 2008 the FOMC announced a single number.
  • The file fomc_statements.csv has one row per statement: 171 statements, 31 Jan 2006 to 16 Sep 2026, 165 of them after scheduled meetings.

Screenshot: federalreserve.gov, statement of 22 March 2023 (public domain).

This is the file the scraping session built. The meeting came 12 days after Silicon Valley Bank failed, which is why paragraph 2 opens “The U.S. banking system is sound and resilient.”

False positives in a large text

R Console; needs fomc
sum(str_count(fomc$text, "rate"))
#> [1] 982
sum(str_count(fomc$text, "\\brate\\b"))
#> [1] 705
caught <- unlist(str_extract_all(fomc$text, "[a-z]*rate[a-z]*"))   # every word containing "rate"
head(sort(table(caught), decreasing = TRUE), 6)
#> caught
#>       rate   moderate      rates moderately  moderated   generate 
#>        705        144         58         42         21          3
  • The literal “rate” matches 982 times, the whole word 705 times. The other 277 are 58 “rates”, which you may want (\\brates?\\b keeps them), and 219 inside other words, such as “moderate” (144).
  • A false positive is text the pattern catches but should skip. In a short test vector you see one at a glance. In 171 statements, a table of everything the pattern caught shows them.
  • unlist() puts every statement’s matches in one vector, so table() can count them.

Splitting text into words

R Console; needs stringr and fomc
i <- which(fomc$date == "2023-03-22")                         # the row of the 22 Mar 2023 statement
fomc$year <- as.numeric(str_sub(fomc$date, 1, 4))             # the year, used in Exercise 2
tokens <- str_extract_all(str_to_lower(fomc$text), "[a-z]+")  # every run of letters
head(tokens[[i]], 12)
#>  [1] "recent"     "indicators" "point"      "to"         "modest"    
#>  [6] "growth"     "in"         "spending"   "and"        "production"
#> [11] "job"        "gains"
length(tokens[[i]])
#> [1] 364
  • Token: one unit of text after splitting, here a word in lower case. Extracting every run of letters does the split: spaces, punctuation and numbers are left out.
  • str_to_lower() comes first so “Inflation” and “inflation” count as one word. tokens is a list with one vector of words per statement, and [[i]] picks one.
  • The apostrophe is not a letter, so “Committee’s” becomes two tokens, “committee” and “s”.

The file’s words column says 365 for this statement. It counts words differently, which is why the slides say tokens.

Word counts and stop words

R Console; needs tokens and the stopwords package
all_words <- unlist(tokens)
length(all_words)
#> [1] 73839
head(sort(table(all_words), decreasing = TRUE), 8)
#> all_words
#>       the       and        to        of committee        in inflation      will 
#>      5320      2854      2576      2382      1706      1534      1330       950
stop_words <- stopwords::stopwords("en")     # pkg::fun(): a package's function without library()
kept <- all_words[!all_words %in% stop_words & nchar(all_words) > 1]   # !x %in% y: x is not in y
head(sort(table(kept), decreasing = TRUE), 8)
#> kept
#> committee inflation  economic      rate   federal    policy    market   percent 
#>      1706      1330       842       705       686       649       642       619
  • Stop words: very common words dropped before counting (“the”, “of”, “will”). The package’s default English list (Snowball) has 175.
  • Term frequency: a word’s count divided by all tokens. “inflation” is 1,330 of 73,839, or 1.8 percent.
  • nchar() counts characters. nchar(all_words) > 1 drops 1,793 more one-letter tokens: the s of “Committee’s” and “U.S.”, and middle initials such as the H in Jerome H. Powell (each statement ends by naming the members who voted).
  • The stop list also drops “not” and “no”, which reverse a sentence, and “against”, which is on the negative word list used for tone.

The prompt and the reply

I have a data frame in R called fomc with a column text that holds the full text of every FOMC statement since 2006, one statement per row. Each statement says what the Fed decided about its policy rate, for example: “the Committee decided to raise the target range for the federal funds rate to 4-3/4 to 5 percent.” Write R code with stringr that extracts the target range from each statement into two numeric columns, lower and upper (here 4.75 and 5).

chat_reply.R in the zip: steps 1 to 3 of the reply's code, unchanged; the lines above them define num and to_num()
# 1. Isolate the part of the statement describing the decision on the funds rate
seg <- str_extract(
  fomc$text,
  regex("decided.*?federal funds rate.*?percent\\b", ignore_case = TRUE, dotall = TRUE)
)
# 2. Pull out "to/at/of X [to Y] percent"
pat <- str_c("\\b(?:to|at|of)\\s+(", num, ")(?:\\s+to\\s+(", num, "))?\\s+percent\\b")
m   <- str_match(seg, pat)
# 3. Convert to numeric
first  <- to_num(m[, 2])
second <- to_num(m[, 3])
fomc$lower <- first
fomc$upper <- ifelse(is.na(second), first, second)

The reply: “For your example, "...to 4-3/4 to 5 percent." gives lower = 4.75 and upper = 5.” The prompt shows one example sentence and gives no other statements to test the code on. What follows reads num, step 1 and step 2 in turn. The full reply is on the session page.

In the str_view() output, “3-1/2” is one match but “3‑3/4” is two, <3> and <3/4>: num stops at the look-alike hyphen, so the row is NA.

  • Code point: the number a computer stores for each character. Unicode is the standard list of them.
  • Character 8209: a non-breaking hyphen. Web pages use it to keep “3‑3/4” on one line. In R, "\u2011" writes it: 2011 is 8209 in hexadecimal (base 16), the form Unicode lists use.
  • The - in a pattern matches only character 45.

The Fed’s pages use character 8209 fifty times, in 34 statements from July 2015 on, and in 12 of them it sits inside a number.

Fixing the reply’s code

R Console; needs fomc, num, to_num() and the FRED columns
# 1. the look-alike hyphen (character 8209) becomes "-"
fomc$text <- str_replace_all(fomc$text, "\u2011", "-")
# 2. stop at the period; 3. three verbs, no "federal funds rate"
seg <- str_extract(fomc$text, regex("(?:decided|maintain|reaffirmed)[^.]*?percent\\b",
                                    ignore_case = TRUE))
# 3. no "to/at/of" before the number
m <- str_match(seg, str_c("(", num, ")(?:\\s+to\\s+(", num, "))?\\s+percent\\b"))
fomc$lower <- to_num(m[, 2])
fomc$upper <- ifelse(is.na(m[, 3]), fomc$lower, to_num(m[, 3]))
fomc$agree <- fomc$lower == fomc$fred_lower & fomc$upper == fomc$fred_upper
table(fomc$agree, useNA = "ifany")
#> 
#> TRUE <NA> 
#>  170    1
  • Change 1: every look-alike hyphen (character 8209) becomes “-”. This fixes the 12 hyphen rows.
  • Change 2: [^.]*?, as few characters as possible that are not a period, replaces .*?, and dotall goes. Inside brackets the dot is a plain period, so the match ends with its sentence. The six 2014 rows now give NA in place of a wrong number.
  • Change 3: step 1 accepts “maintain” and “reaffirmed” and drops “federal funds rate”, which can come after the number (“the current 0 to 1/4 percent target range for the federal funds rate”). Step 2 drops “to|at|of”, since “current 0 to 1/4” has none.

When to use regex

Regex works well when

  • the text follows a format: IDs, dates, amounts, codes
  • the wording repeats, as in the Fed’s sentence that states the target range
  • you can list the variants and test each one
  • you need the same answer every time the code runs
  • the corpus is large: a pattern runs on millions of documents in seconds, for free

Use a parser or a model when

  • the meaning depends on context or on negation: the Fed’s “might not be strong enough” (13 Sep 2012) scores as positive
  • the same idea is written in more ways than you can list
  • the text is a web page (HTML) or data from an API (JSON), where parts sit inside other parts
  • the variable is a judgment call, such as whether a sentence signals that the Fed will raise its rate

Parser: a function that reads a structured format into its parts, such as jsonlite::fromJSON() for JSON or rvest::read_html() for a web page. Model: a language model, the kind of program behind a chatbot, asked to read each text and return a label, or a statistical classifier trained on texts that people labeled by hand.

A pattern gives NA or a wrong number, with no error message, when the wording or a character changes. A chatbot can write the pattern. You still read it, test it on strings from your documents, and compare its output with a second source such as FRED.

What net tone misses

The target range has a second source, FRED, and 170 of 171 values now equal it. Net tone has no second source, so its errors show only when you read the sentences it scored. The finance word list scores each word on its own:

R Console; needs fomc
s <- str_extract(fomc$text[fomc$date == "2012-09-13"], "economic growth might not[^.]*")
str_view(s, "\\b(not|strong|improvement)\\b")
#> [1] │ economic growth might <not> be <strong> enough to generate sustained <improvement> in labor market conditions
  • Negation. 13 Sep 2012 (also 24 Oct and 12 Dec 2012): “strong” and “improvement” count as positive. Each word is scored on its own, so the “not” before them changes nothing.
  • Context. 25 Apr 2012, “the unemployment rate has declined but remains elevated”: “unemployment” and “declined” count as negative, although a falling unemployment rate is good news.
  • The event behind the words. 3 Mar 2020, a cut in the target range between scheduled meetings as the coronavirus spread, is the 8th most positive of 171 statements. “strong”, “achieving” and “stability” count as positive. “coronavirus” and “risks” are on neither list.

The full 13 Sep 2012 sentence opens “The Committee is concerned that”, and “concerned” is on the negative list, so the sentence nets +1. Shapiro and Wilson ignored words after “not”, ran their estimates without “unemployment”, and filtered phrases such as “price stability”; their estimates barely moved (working paper version).
